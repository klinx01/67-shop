# Development Diary: Core Routing & Authentication State Management

## Task Description
The goal was to configure the application's core routing architecture and implement a secure, reactive authentication mechanism to protect private routes like the shopping cart.

## What was done:
1. **Core Routing Setup:**
   - Established functional routing using Angular's modern `Routes` configuration.
   - Bound the `HomePage` component directly to the root path (`''`) for a clean base URL (`/`).
   - Configured a wildcard fallback route (`**`) to catch all invalid URLs and redirect users to a custom `/404` page.
   - Replaced hardcoded application layout components inside `app.component.html` with a dynamic `<router-outlet></router-outlet>`.

2. **Lazy Loading Optimization:**
   - Implemented lazy loading via `loadComponent` for the `NotFound` component to optimize the application's initial bundle size and boost performance.

3. **Reactive Authentication State (Angular Signals):**
   - Created an encapsulated `AuthService` utilizing Angular Signals (`isLoggedIn`).
   - Followed architectural best practices by exposing the state as a `public readonly` stream via `.asReadonly()`, ensuring the state can only be mutated internally by the service itself (Single Source of Truth).

4. **Functional Route Guards:**
   - Developed a modern functional `authGuard` using the `CanActivateFn` signature and the `inject()` function.
   - Protected the `/cart` route, automatically redirecting unauthenticated users to the 404 error page.

## Challenges & Solutions
- **Issue:** Encountered a TypeScript compilation warning (`declared but never read`) regarding unused parameters (`route`, `state`) inside the functional guard.
- **Solution:** Cleared up the codebase and bypassed the compiler constraint by removing the unused arguments from the `CanActivateFn` parameter list, as they weren't strictly necessary for the signal evaluation logic.

## Summary / Conclusion
The foundational routing layer and initial security guard are fully operational, tested, and integrated into the `dev-sprint-2` branch. The app now handles navigation seamlessly and guarantees that private routes are securely shielded.


- **Time spent:** 8 hours
